## OCR 入口降级改造（审核前修复）

问题：`config.ocrEndpoint` 为空时，录入页「拍照 OCR」tab 直接渲染两段面向开发者的技术报错（Tesseract/WASM/config.ts 路径），用户与审核员都会看到不可用功能。

改法（`miniprogram/pages/add/`）：
- tab 改为对象数组 `{key,label}`，按 `OCR_ENABLED = Boolean(config.ocrEndpoint)` 动态构建：未配置时只留「手动录入」「批量粘贴」，默认落在手动录入。
- wxml 条件从 `tabIndex === N` 改为 `tabKey === 'ocr'|'manual'|'bulk'`，`wx:key="key"`。
- 删除 OCR 技术报错节点与 `ocrConfigured` 数据字段；`onPickImage`/错误分支文案改为「拍照识别暂未开放，请使用手动录入或批量粘贴」。
- AI 未配置文案从「尚未配置 API Key」改为用户可理解的「AI 补全未开启，可在设置中配置」，避免审核误判。

后续若要真正启用 OCR：需要 HTTPS+备案域名的服务端接口（或云函数 + 腾讯云 OCR），再把 `ocrEndpoint` 填上并把域名加入 uploadFile 合法域名，tab 会自动出现。

## 拍照识别改为 DeepSeek 视觉模型（已落地 + 真实调用验证）

方案：`miniprogram/core/ocr.ts` 支持两条路径，按优先级自动选择——配了 `ocrEndpoint` 走服务端 OCR，否则有 AI Key 时走 DeepSeek 视觉模型（`deepseek-v4-flash-vision-exp`），两者都没有则隐藏「拍照识别」tab。

代码改动：
- `core/ocr.ts`：新增 `resolveOcrMode()`、`mimeFromPath()`、`toDataUrl()`、`buildVisionBody()`、`parseVisionLines()`、`recognizeByVision()`；图片先 `wx.compressImage`（1600px，基础库 2.26+ 才支持，缺失则跳过）再 readFile base64 拼 data URL，`wx.request` 直连 `/v1/chat/completions`，timeout 60s。
- `config.ts`：新增 `visionModel` 字段（模型改名只改这里）。
- `pages/add/index.ts`：tab 按 `ocrMode` 动态构建并在 `onShow` 重算（设置页改 Key 返回自动出现入口）；`onPickImage` 按模式分流。
- `pages/settings/index.wxml`：说明 Key 同时开启拍照识别。
- `package.json`：新增 `test:ocr` / `test:ocr:live` / `fixture:ocr`。

测试：
- `miniprogram/__tests__/ocr.spec.ts`（15 例）：模式选择、MIME、请求体、行收敛（代码块/序号/中文截断/问号低置信/去重）、错误映射。
- `miniprogram/__tests__/ocr.integration.spec.ts`（5 例）：本地 HTTP 服务模拟 OpenAI 协议，验证真实网络链路的 URL/鉴权头/body/400KB 大包/429 与 400 错误翻译。
- `miniprogram/__tests__/ocr.live.spec.ts`（2 例，无 Key 自动 skip）：真实调用 DeepSeek，样本 `tests/fixtures/ocr-wordlist.png`（由 `scripts/make-ocr-fixture.mjs` 用 Chrome 渲染生成）。
- 真实调用结果：8/8 词全中，4.0s；额外 240px 宽 / 10px 字号小字样本 11/11 全中，8.3s。模型缩图后仍可用，但仍需人工校对。

上线前必做：mp 后台「开发设置 → 服务器域名 → request 合法域名」加 `https://api.deepseek.com`，否则真机失败（模拟器勾了不校验域名看不出来）。Key 由用户在设置页填写，存本机 Storage，不入库不入备份。
